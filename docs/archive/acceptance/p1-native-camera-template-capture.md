# P1 原生相机模板与真实拍摄验收

2026-10-19。对应清单11.5；仅部署MarginStudy验收库。11.5和父项11仍未整体关闭。

## 本轮结果

macOS相机由上一轮ImageKit面板改为公开AVFoundation与AppKit实现，按本轮MN4实机观察对齐黑底无标题面板、快门/Cancel，以及拍后Retake/Use Photo。面板580×640pt，圆角16pt；画面按比例呈现，不拉伸。用户准备测试书后，插件真实拍摄、重拍、Use Photo、Swift PNG编码、独立PDF附件、页序列插入和真实插件重载均已通过。

最终本机照片1760×1328；这仅是插件本机实测输出，**原版确认后输出像素尺寸尚未测得**。不是所有设备、窗口和像素细节已经完全等价。

## 原版MN4的L4观察

- 本轮打开样例页编辑的Camera入口，实际面板为黑底无标题，截图1160×1280像素，对应580×640pt；此前假定的ImageKit模板不符。
- Live为居中按比例画面、底部中央灰底红色快门和右侧Cancel；拍后为约72pt底栏，左Retake、右Use Photo。
- 用户准备测试书后实际拍摄，进入确认页；Retake回预览，随后Cancel。原版出现“Photo Addition has been canceled or failed”，已点OK关闭。
- **本轮没有点击原版Use Photo**，没有完成原版照片输出/最终插页对照。原版保留原四页，最后双击空白退出页编辑。
- 证据01、02、02b和45为原版AX；其余插件证据不能替代原版结果。没有新增L3结论或照搬私有类名/API。

## 实现与失败修复

`native-src/CameraPicker.swift`重写原生UI与相机生命周期；`scripts/build-native-camera.mjs`更新构建指纹。沿用LaunchServices启动和随机请求目录/result.json协议。

拍后冻结图仅在内存中；Use Photo才编码0000.png，Retake丢弃冻结图。仅创建视频input，没有麦克风input或上传。照片应用EXIF方向、校验边长/总像素；取消、Cmd+W、Cmd+Q及请求目录失效会退出。session启停与配置使用串行队列，UI回主Actor。

本轮保留以下失败，未改写成通过：

1. 第一版AVFoundation实际拍摄/确认/重载成功，但为1920×1080宽幅，与本轮原版预览比例不符，故继续修复。对应05—08、14。
2. 使用inputPriority曾因macOS SDK不可用而构建失败，10日志保留，后续移除。
3. 只在初始配置时选1760×1328并设置照片尺寸，**不能保证启动后仍采用该格式**。17系统日志显示先设1760×1328，再被切回1920×1080；按快门时出现NSInvalidArgumentException，工具AX点击同时返回failure，未进入确认页。异常具体参数在系统日志中为private，不能将其写成已读到的错误文本。SDK要求照片尺寸属于当前activeFormat，旧配置存在不一致。
4. 最终改为每次startRunning完成后选择原生4:3格式，再从实际activeFormat读取有效照片尺寸，完成后才启用快门；初次打开和Retake走同一路径，并补最终拍摄错误回调。18最终构建成功无该编译警告；21—27真实拍摄和重拍通过。

## 授权与宿主开关
