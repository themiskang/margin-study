## 必须继承的用户要求

1. **最高目标**：桌面版 MarginStudy 与 MarginNote 4 的功能、布局、呈现、模板、按钮做到完全一致；不能擅自降成“相似功能”或“能用即可”。当前仍有差距，阶段通过不代表全插件完成。原话见旧日志 ordinal 2933、3933、13357。
2. **范围**：只需要桌面版。用户没有跨软件数据迁移需求，重点是实现功能。ordinal 440、1035。
3. **方法**：结合已有 REA 分析、原版实机行为及官方手册/论坛确认差距；原版不清楚的功能可以实际操作验证，Max 权限曾由用户明确说明已可用，开始新实测时仍确认当前状态。ordinal 1167、2933、3559。
4. **证据规则**：L3 是已实测反汇编调用链；L4 是实际运行观察；推断、遗留、未确认项不能当事实。实现以 Qoder `evidence/` 每份 L3 附档的“最小行为契约”及后续实机修正为依据；不照搬 MN4 类名、CoreData 或私有 API，使用插件自己的模型。ordinal 1992。
5. **工具复用**：沿用现有 REA、具体分析工具、脚本和静态产物。复核 L3 时使用 `tools/` 和 `static/`，不要重装或依赖 Ghidra；不因换聊天重复下载。确实缺失的组件先核实再处理。旧日志 ordinal 1992，加当前聊天的明确补充。
6. **界面验收**：不能以菜单入口存在、编译通过或自动检查通过代替真实点击和原版对照。用户指出的问题要在准确页面复现，尤其 AQ 前浏览页不能用问答评分页代替。ordinal 7447、7483。详细标准引用现有验收计划。
7. **已允许的宿主适配**：进入学习插件时自动收起 Obsidian 左右侧栏；这是用户明确允许与 MN4 不同的宿主适配。Claudian 浮动输入框不能遮挡学习页面。ordinal 13238、13357。
8. **AI 联动**：优先利用用户原有 Obsidian AI 插件和已经配置 API 的原仓库；不能把验收库中新建且未配置的 Claudian 视为已接通。ordinal 4911、5714、7208。当前正式库部署和全链路验收仍遵循已有记录的范围。
9. **协同条件**：质量和最终完成度必须达到主代理自己处理的标准；困难任务由主代理做，简单重复任务才考虑辅助 agent 或 Qoder。先通过任务级校准，安排转交时主动告诉用户。确实需要 Qoder 尚未给出的结果时，停下依赖该结果的步骤等待用户提供，不猜测补齐。ordinal 1877、7988、8010、8056。
10. **窗口与进展**：不要把工具失败归咎于用户；用户可切应用和桌面。再次断连先重点诊断原因；避免多开第二份 MN4。简短报告实际推进，不能长时间只整理或重复报告而没有实质进展。ordinal 9596、12740、18021、18352、19135、20571。
