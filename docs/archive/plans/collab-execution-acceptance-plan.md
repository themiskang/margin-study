## 交接前必须完成的校准

1. **主代理先做样例。** 使用已复核的原始材料，写明前置状态、步骤、实际观察、证据路径、版本、未确认项和完成边界。首份样例见 [AQ 前浏览页标准样例](协同标准样例-AQ前浏览页.md)。该样例基于已有实机证据整理，不代表今天新执行了一轮实机操作。
2. **任务包可直接执行。** 指定唯一任务编号、输入文件、允许操作范围、预期交付文件、停止条件和验收项；依赖、权限、桌面交接及未知点均写清楚。主代理先核对文件确实存在，不能要求协作者自行猜出任务背景。
3. **先校准一项。** 第一项只读整理一个已保存状态的证据，暂不编辑插件、运行原版或同时分派多页操作。先检查协作者能否保留证据边界、正确指出缺口。
4. **主代理逐项复核。** 核对每个按钮、状态、证据引用及结论，不使用抽样比例或平均分替代关键项通过。所有适用项都满足时，该任务包才可交接执行；有错误就修改任务书或收回处理。
5. **达到标准再扩展。** 首项校准通过仅说明此类任务适合交给该协作者；切换到新类型、换人或扩大到实机操作时，重新确认输入、边界和样例。疑难问题仍由主代理处理。

校准检查项：

- [ ] 同样输入下，交付覆盖主代理样例要求的全部适用字段、状态和结果。
- [ ] 每条关键结论能定位到实际存在的原始证据；文字与截图/记录一致。
- [ ] 明确区分静态结论、实机观察、历史记录、推断和未覆盖状态。
- [ ] 对缺证据、操作失败、版本差异、内容或窗口尺寸不同没有擅自补全结论。
- [ ] 操作步骤足以重放，不依赖记忆或坐标猜测。
- [ ] 没有擅自修改插件、正式库、真实笔记或其他协作者使用中的材料。
- [ ] 主代理已独立复核交付；遗留项已明确收回或补齐。

本清单尚未勾选。整理出样例、计划审查通过及任务书写完，都不自动意味着任务级校准通过。

## 分工

| 角色 | 负责范围 | 首轮具体工作 | 交付物 |
|---|---|---|---|
| 主代理 | 疑难缺陷、架构和数据模型、跨模块行为、代码修改与整合、最终验收 | 清单 01—04：菜单遮挡、看板 Markdown、文档恢复、改名与关闭交错；确定 05 的对照口径 | 修复、必要的行为回归、真实 Obsidian 证据、更新清单 |
| Qoder | 按指定步骤操作原版、截图、记录菜单与模板，重放已有脚本 | 为清单 05—08、10 采集当前原版的页面与状态；每批限定少量页面，先交第一批 | 状态清单、截图、逐步操作记录、观察结果与未确认项 |
| 辅助 agent A | 整理现有材料与机械核对 | 只读检查已有证据索引，列出缺截图、缺版本、缺操作步骤的条目；核对新交付是否满足格式 | 证据完整性检查表，附原始路径 |
| 辅助 agent B（按需） | 按固定检查表复查 | 对指定页面检查按钮顺序、标签、禁用/选中状态、截图尺寸及宿主样式；不自行重构 | 带具体页面和证据路径的差异表 |

首次校准只使用一个辅助方；校准通过后最多使用两个辅助 agent，没有独立任务时不启动额外 agent。Qoder 在本方案中是外部协作者，任务书已准备不等于任务已发送或已执行。

## 第一批执行顺序

1. 主代理完成标准样例并核对任务包；保留已通过版本的快照与核对值。
2. 在主代理准备好并告知交接安排后，安排一个只读校准任务，逐项复核交付。此时不启动原来的整批 Qoder 任务。
3. 任务级校准通过后，主代理明确告知可转交的文件、接收方、范围和桌面交接条件，再开始少量原版页面取证或资料整理。
4. 清单 01—04 已按记录范围完成；主代理继续建立 05 的页面/菜单/状态对照并处理困难差距。辅助方只在明确范围内工作，复用已有证据，不重复六专题完整反汇编。
5. 主代理检查实际交付，形成清单 05 的逐页对照表；对争议结论亲自复核。
6. 主代理完成修复并运行必要检查，在真实 Obsidian 中对照原版截图、点击关键操作；达到原定质量后再扩大分工。清单 11—32 的技术难点仍由主代理逐项处理。

下一批若确实需要尚未取得的 Qoder 证据，主代理先完成不依赖该证据的工作，并列明待交付项；依赖它的行为不靠猜测补上。到需要外部结果的节点，遵循用户既有要求停下等待其提供结果。

## 何时通知用户与如何交接

- 需要用户转交文件、切换辅助方、让出桌面或补充外部结果时，主代理在该节点主动说明，无需用户反复询问。
- 通知包含：交给谁、为什么此时交接、唯一任务编号、任务书与所需输入文件、允许操作范围、交付位置、主代理接下来做什么。
- 内部辅助 agent 可由主代理直接协调；更换参与者或职责时向用户说明。Qoder 当前没有已确认可用的直接连接，准备好后由用户转交；若以后建立明确可用的渠道，再直接执行同一任务包。
- Qoder 正在操作桌面时，主代理只做代码或已有文件分析；桌面归还后再进行插件实机验收。
- 当前没有新的执行交接：用户无需发送此前任务书；先完成交接准备与任务级校准。

## 文件与实机操作安排

- 当前开发目录是 `MarginStudy开发`；正式 `yan` 插件与原始开发源码继续保留基线。
- 当前目录不是 Git 仓库。只读任务无需工作副本；以后若委派独立的小改动，先从同一开发快照建立任务副本，明确可改文件，再由主代理审核差异并合入。协作者不同时改主线同一文件。
- 共享样式、工作区控制、数据模型、持久化与最终构建由主代理统一处理。不能为了便于并行而拆散相互依赖的改动。
- 一个时段只允许一个操作者控制桌面应用。主代理操作 Obsidian 或 MarginNote 4 时，Qoder 不同时操作桌面；先约定交接时段。其他协作者只读取已落盘材料。
- 目前不默认让 Qoder 自动开始操作，也不默认已能直接向 Qoder 发送消息；由用户转交任务书，或在已有明确可用渠道时执行交接。

## 每份协作交付的固定格式

| 字段 | 要求 |
|---|---|
| 任务与范围 | 对应清单编号、页面和状态；一批一个清晰范围 |
| 版本与环境 | 原版/插件版本、桌面窗口尺寸、样例名称、相关设置 |
| 复现步骤 | 起始页面、进入路径、按钮标签与动作；坐标不能作为唯一说明 |
| 观察结果 | 点击前后各发生什么；预期与观察分开，不把推测写成结果 |
| 原始证据 | 截图、录屏或操作/AX 记录的实际文件路径；一次性样例可重放 |
| 证据级别 | 按条目标明 L0—L4；静态调用链是 L3，实机观察才是 L4；未确认项单列 |
| 最小行为契约 | 仅描述输入、操作、输出和状态变化，供插件独立实现；不要求照搬原版内部结构 |
| 结论 | 已观察、未覆盖、操作失败、存在分歧分别说明；未覆盖不能填“通过” |

原版静态材料为 4.4.5，已有实机材料为 4.4.6；新观察记录当时实际版本，版本差异不自动视为同一行为。已有静态结论需要重放时，使用 Qoder 证据目录中的 `tools/` 与 `static/`；不以重新安装 Ghidra 为前置条件。

## 合入和完成标准

每项改动合入前，由主代理核对以下事项：

- [ ] 改动对应已确认的行为或已复现的问题；存在疑点时已复核原始证据。
- [ ] 修改范围明确，与当前主线整合后没有遗漏其他协作者的结果。
- [ ] 跑过与本次改动有关的必要检查；阶段构建通过，既有关键流程没有退化。
- [ ] 涉及界面的改动在真实 Obsidian 中检查，宿主按钮样式、弹层和点击均正确。
- [ ] 用相同样例与相近窗口尺寸对照原版，核查布局、文案、顺序、状态和实际动作。
- [ ] 保存、关闭重开、取消、撤销/重做等相关状态仍正确。
- [ ] 证据、限制及 [后续工作清单](后续工作清单.md) 已更新；局部通过没有写成全面等价。

主代理据此判断完成。增加 agent 数量、报告“已做完”或单独的自动检查通过，都不能替代这些标准。
