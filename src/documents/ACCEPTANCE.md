# 阅读器与批注验收

在开发副本根目录运行 `node src/documents/acceptance.mjs`。需要已安装依赖、已构建的 `pdf.worker.js` 和可用的 `agent-browser`。

脚本在系统临时目录创建合成 PDF、EPUB、HTML、Markdown、Word 数据及空内存存储，启动仅监听本机的临时服务和独立浏览器会话。不会连接真实 Obsidian，不会读写真实笔记或安装版插件；完成后自动关闭浏览器和服务，保留结果路径供核查。

78 组行为覆盖（最新 2026-10-16）：每笔手写提交、文字引用重定位/重复歧义拒绝、章节定位、分屏批注共享和来源卡片、EPUB2/3 数据通路中的 EPUB3 目录样例、ZIP 路径/展开体积/DRM 拒绝、HTML 静态清理、通用阅读器切换/搜索/目录/位置/回跳、Markdown 原生渲染适配、PDF 切换/缩放/缓存/折叠/关闭、回忆遮罩/删除线/备注更新、Word 切换/重载、录音首次保存/关闭等待/错误清理、OCR 排序，以及真实 PDF.js Worker 的解析/析构和主窗口全局隔离。文档笔记本、虚拟原页引用、目录解析、手写设置和自由批注的覆盖详见下文。

遮挡集成另有三组：PDF 同批注跨页一起揭晓/再点收回、singlePeek、重绘后保留临时揭晓、全部摘录/仅标记遮挡、卡片与当前画布节点布尔状态、切画布清空临时状态、区域遮挡；HTML 跨文字节点同组揭晓与重建恢复；Word/通用文档工具栏接入。内存 Store 适配器计数证明这些揭晓、重绘、退出/进入和范围切换没有调用持久化入口，三类阅读器关闭后退订数为零。这一计数验证不是实际笔记库的磁盘写入审计。

真实 PDF 的测试直接检查内部通信对象确实为浏览器 Worker，不能以“尝试创建过 Worker”代替成功。PDF 竞态、跨页与历史样例和 Word 转换分别使用可控延迟适配器；几何投影与旋转文字覆盖层另用真实 PDF.js 验证。Obsidian API 用最小模拟，因此这些结果不证明真实 Obsidian 集成、原版 MarginNote 的 L4 运行时行为一致或功能全面覆盖。
